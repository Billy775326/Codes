# Codes regression test cases

These cases cover the implemented Codes workspace, including the settings dialog and the centralized **Backup & restore** page. Each row describes a fixture or initial state, an action, and an observable result. Test file links are starting points for implementation and review. Execution results belong in [Acceptance](acceptance.md).

## Environments and pass criteria

- **Browser and service tests** use the simulator with a temporary Codes data directory, Codex home, and project. Seed two conversations in different directories, one archived conversation, and long history. Use separate browser contexts when testing concurrent clients. The browser suite binds loopback port 19140.
- **Native tests** use the compatibility versions in [Development](development.md#checks). Use metadata smoke for protocol and configuration support. Use a disposable Git project and authorized model account for real execution, permissions, questions, or review.
- **Deployment tests** use a disposable service instance, a representative proxy and filesystem, a physical phone, and copies of backup data. Record timing and memory alongside the data size in scale tests.
- Run UI cases on desktop and at 320 CSS px. Include English and Simplified Chinese, light and dark themes, and System theme with a simulated OS change. Exercise keyboard and touch where the controls differ. Run high-risk cases at the relevant widths and layers.
- Record the case ID, build or commit, fixture, runtime, result, and reproduction evidence. For send, queue, answer, archive, and restore cases, verify persisted IDs, state, and operation counts after refresh or restart. Request success alone is insufficient.

## Release verification

Run the repository's unit, integration, and simulator-browser suites first. Run native metadata checks for the versions in CI and the intended installation version. Task, approval, question, review, and compaction cases need a real Codex run to verify model and native callback behavior.

Use a disposable deployment for the proxy path in AUTH-05 and OPS-05, restart recovery in QUEUE-06, and coordinated recovery in DATA-08. Capture measurements for OPS-06 with the intended data sizes. Record native and deployment results separately from simulator results.
